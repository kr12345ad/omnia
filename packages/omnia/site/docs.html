Omnia documentation

Omnia is a desktop agent that runs tasks on your computer. This guide follows the shipping app: install it, sign in, run a session, choose a model, change settings, answer permission prompts and connect other machines.

Getting started

Install

Download the build for your platform from the downloads page. The Linux AppImage runs directly; the deb and rpm packages add a menu entry. macOS builds require macOS 13 or later. Windows builds require Windows 10 or later on x64.

Each artifact has a SHA-256 digest in /downloads/SHA256SUMS. Verify it before running:

sha256sum -c SHA256SUMS

First launch

Omnia opens on a full-window sign-in gate. The gate stays up until sign-in completes, so the rest of the app cannot be used without an account. The screen reads Sign in to Omnia above the line "Use your GitHub or Google account to sign in or create an account."

Continue with GitHub and Continue with Google open the provider in your browser. The app shows "Waiting for GitHub..." or "Waiting for Google..." and finishes when the callback returns. If the provider reports an error, Try again restarts the exchange.

GitHub also offers Use a device code instead. That path shows a code with Copy code and Open GitHub; enter the code on GitHub and the app completes the sign-in. Use the GitHub CLI session reuses an existing gh login.

After sign-in

Omnia stores the credential on this computer. On a first install, the Welcome to Omnia setup follows. Bring your sessions imports detected OpenCode databases and Codex session files. Your first project creates the first folder with Create default project. Skip setup bypasses both steps; the import stays reachable later from Settings.

The account menu at the top right shows the avatar after sign-in. Settings, Account shows the plan and usage. Sign out in the account menu clears the credential and returns to the gate.

Home screen

The home screen is a new session draft. The session sidebar sits on the left; the composer, quick actions and project selector sit in the center.

  1. New session opens a draft tab in the selected project. The draft takes the next prompt.
  2. Search sessions turns the row into a field and filters the session list as you type. With a project selected, the placeholder reads Search sessions in followed by the project name, and results stay inside that project.
  3. The recent sessions list groups sessions under Today, Yesterday and Older. Selecting a title opens that session in a tab; the selected row stays highlighted.
  4. The project selector at the bottom of the composer shows the current project, here Default Project. Opening it gives a Search projects field, the project list and Add project. Choosing a project changes the folder the draft runs in.
  5. Add project opens the system folder chooser on desktop and adds the chosen folder to the project list. The web app has no folder chooser, so adding a project is a desktop action.
  6. The composer starts the session. The plus button attaches images and files, the model chip opens the model picker, the variant label sets reasoning effort and the arrow sends. The full control list is under A session.
  7. Quick actions fill the composer with a starting prompt. Research, Organize files, Spreadsheet, Use an application, Browse the web, Create an agent and Create a superskill each add text you can edit before sending. Discussion Room opens the New discussion dialog instead.
  8. The Superskills row shows the saved count. Manage opens Settings, Superskills.
  9. Settings opens the Settings window on General.
  10. Chat Channels opens Settings on the Chat Channels tab.
  11. Help opens the Omnia feedback page in your browser.
  12. The utility nav at the bottom groups Settings, Chat Channels and Help. When the sidebar collapses, the same rows become icons.
  13. The account menu at the top right offers Sign in when signed out. Signed in, it shows the avatar, View GitHub profile and Sign out.
  14. The titlebar holds the sidebar toggle, the Agent and Chat tabs, the browser panel toggle, the tab strip and the plus button. They work as described under A session.

A session

A session lives in a tab. The titlebar runs the tabs and modes, the timeline holds the conversation, and the composer takes the next prompt.

  1. The sidebar toggle collapses the session list to an icon rail. The same control restores it.
  2. The tab strip holds New session and every open session. Select a tab to switch; the close button on a tab closes it without deleting its history; the plus button opens a new session tab.
  3. Toggle browser opens the built-in browser beside the conversation. The same button closes it.
  4. The mode control offers Agent and Chat. Agent runs tools; Chat answers without tools. The mode is fixed when the session is created, so start a new session to change it. Older builds called Chat Code; those sessions reopen as Chat.
  5. The timeline shows your message, the answer and the work between them. Tool cards name the tool and hold its result behind a fold. Expand a card to read the arguments and output. Shell and edit cards can start expanded from Settings, General.
  6. Thinking blocks appear when Show reasoning summaries is on. Expand one to read the model's summary.
  7. Approval cards pause the run and sit above the composer. They are covered under Permissions and approvals.
  8. Diff cards show file edits with the path and the added and removed lines.
  9. The composer at the bottom takes the next prompt. Its controls are listed next.

Composer controls

Describe the task to do. The composer holds the prompt and the controls that decide how it runs.

  1. The plus button, labelled Add images and files, opens the attachment picker. You can also drop images, PDFs and text files on the composer.
  2. The model chip shows the current model, here DeepSeek V4.1 Flash. Selecting it opens the model picker.
  3. The reasoning variant label shows Default, Max or another effort. Selecting the label opens a short slider; choose a stop to set the effort, or press Esc to close the slider unchanged.
  4. The context meter, here 196k, shows the context in use. Hover or focus it to read used tokens out of the model limit and the percentage.
  5. The arrow sends the prompt. While the agent works it becomes Stop; selecting it stops the run and keeps the transcript.
  6. Type / at the start of the prompt to open the slash menu. The list holds commands, skills and MCP tools; choosing one inserts or runs it.
  7. Type @ after a space to open the context menu. The list holds files, agents and the active selection or comments; choosing one inserts a mention that attaches it to the prompt.
  8. Enter sends, Shift+Enter adds a line, and Esc closes the open slash or @ menu and leaves shell mode.

Model picker

The model chip in the composer opens the picker. The list shows the models this build can use, with the selected model checked.

  1. The search field, Search models, filters by company and model name as you type. The clear button restores the full list.
  2. Each row starts with the company logo, then the model name.
  3. Free marks a model with no input price. Latest marks the newest model in its family.
  4. The price at the right is input/output per million tokens. $8/$40 means $8 per million input tokens and $40 per million output tokens.
  5. Selecting a row makes it the model for the next prompt and closes the picker. The chip updates to the new name.
  6. Manage models at the bottom opens the model manager, where each provider and model has a switch that controls whether it appears in this list.

Esc closes the picker without changing the model.

Settings

Settings opens in its own window with a sidebar. Desktop holds General, Account, Chat Channels and Shortcuts. Computer holds Superskills, MCP Marketplace, Memory, Computer use and Computers. Server holds Servers, Providers and Models. The version is at the bottom.

General and Appearance

  1. Language changes the display language. English is the default.
  2. Auto-accept permissions approves permission requests in the open project without showing a card. Switch it off to bring the cards back.
  3. Terminal shell picks the shell for terminals and agent commands. Auto (Default) uses the system shell.
  4. Show reasoning summaries adds thinking blocks to the timeline.
  5. Expand shell tool parts and Expand edit tool parts make those cards start open in the timeline.

Permission scopes are separate: screen reading, pointer and keyboard control, clipboard, running processes and secrets each asks for approval.

  1. UI Refresh switches between the current tabs and home layout and the previous layout.
  2. Color scheme sets System, Light or Dark. Theme sets the palette, here OC-2.
  3. UI Font, Code Font and Terminal Font set the type used in the interface, code blocks and terminal.
  4. The Notifications section below sets system notifications for Agent, Permissions and Errors, and the sound rows set the sounds for the same events.

Account and previous sessions

Signed out, the page reads "Sign in to see what your plan allows." Signed in, it shows the plan name and price, Upgrade to Pro, Upgrade to Business, Manage Billing, and Usage limits with a bar for each finite allowance and its reset date. Scheduled runs on the same page create recurring tasks: name the run, write the prompt, set Repeat every (minutes), then Schedule run; Enable, Pause and Delete manage it.

Session import is part of account setup. Bring your sessions lists OpenCode databases and Codex session files with session and message counts. Import selected copies the chosen sessions and messages; the originals are never modified. The import panel also offers Rescan to look for new files.

Shortcuts

Settings, Shortcuts lists every command with its current binding. Click a binding and press the new keys; Reset to defaults restores the shipped map. Search shortcuts filters the list. A conflict warning names the command that already holds the keys.

Superskills

  1. New superskill opens the editor for a hand-written superskill: name, ID, description, UI instructions, an optional bridge (Local command (stdio) or HTTP endpoint), methods JSON and an Enabled switch. Save stores it; Test runs the bridge; Delete removes it.
  2. Create with AI takes the description and sends an agent to inspect the application, write the UI instructions and save the result. It needs an open project. The example describes a LibreOffice Calc superskill that knows the menus, dialogs and how to fill and verify a spreadsheet.
  3. The list below holds saved superskills. The switch on a row enables or disables it; selecting the row opens it for edits.

MCP marketplace

  1. Search servers filters the catalog as you type.
  2. Filters opens Runtime and category choices. Runtime covers All runtimes, Node.js, Python, Docker and Other.
  3. Sort by orders the list by Popularity or Name, A to Z.
  4. Browse and Installed (0) switch between the catalog and the servers already in your configuration. The count at the top right is the size of the catalog.
  5. Details opens the server page with the install command, configuration and documentation. Install adds the server; a row marked Needs setup asks for its fields first.
  6. On the Installed tab, Load on startup decides whether the server starts with Omnia; Settings edits its configuration; Remove deletes it.

Local servers run as your user on this machine. Read the command before installing.

Memory

Memory keeps application quirks, procedures and preferences between sessions. Settings, Memory lists each entry with its scope and confidence. Search memories filters the list; the scope row narrows it to All, Session, Task, Workspace, User, Skill or Application; Delete memory removes one entry; Forget all clears the store. Memories by scope shows the counts. The agent reads matching entries when a task needs them.

Computer use

  1. Runtime reports whether the local llama.cpp runtime is ready. The CPU runtime ships with the app; GPU builds download on demand.
  2. Engine shows the accessibility engine in use, here Legacy accessibility engine.
  3. Allow model downloads lets Omnia fetch model weights from Hugging Face on demand. Downloads are large and stored on this computer.
  4. The model list below the runtime shows each local computer-use model with Download, Load, Unload and Delete. With no models installed it reads "No local computer-use models are available."
  5. Display calibration measures how pointer input maps to screen pixels. Calibrate display moves the pointer to known points and saves the scale and offset; Reset clears the result; a changed display size marks it stale.
  6. The audit log lists every computer-use action with its aim point, permission decision and verified outcome. Filter by computer, since date and Verified actions only; Refresh reloads the list.

Models stay in your Omnia data folder and are never uploaded.

Computers

  1. Add computer opens Pair a computer and generates a pairing code. On the other computer, open Settings, Computer, Computers, choose Pair with a code and paste the code. Copy code copies it; an expired code is replaced with New code.
  2. Pair with a code joins this computer to another. Paste the 8-character code shown on the other computer and select Pair with a code.
  3. The list shows Connected or Stopped; Connect and Stop change that state without deleting credentials. Unpair removes the pairing.
  4. Selecting a computer opens Credentials. Add credential stores a name, a kind (Password, Username and password, Token), the secret and the rules that decide when it is used: Command contains, Application is or URL starts with. Save stores it; Delete credential removes it.

Everything is stored on this machine. Secrets are never shown to the model and never leave this machine. A paired computer runs its own Omnia runtime; this app sends approved actions to it.

Chat channels

The Chat Channels row in the sidebar opens Settings, Chat Channels. Pick a platform (Slack, Telegram, Microsoft Teams, Google Chat, Discord, GitHub, Linear or WhatsApp); the panel lists the fields it needs and a Setup guide. Polling platforms need no public URL. Webhook platforms show a Webhook path with Copy. The Omnia server holds the connection, so the agent keeps answering while the desktop window is closed. Connected channels show Connected and a received-message count.

Permissions and approvals

A tool that needs a capability pauses the run and adds a Permission required card above the composer. The card names the tool and the target: a command, a path, a URL, or a computer-use control. For computer use it adds the aim point and a Highlight target preview that shows where the click will land.

Three buttons decide the request.

  1. Deny refuses this request. The action does not run, and the agent receives the refusal.
  2. Allow always allows this request and matching requests for the rest of the session, so the card stops appearing for them.
  3. Allow once allows this request only; the next matching request asks again.

What stays blocked

  • A denied action does not run. The agent sees the refusal and must choose another path or stop.
  • Computer-use targets marked guess are not resolved controls. The card says so, and the action stays unverified until the outcome is checked.
  • The hosted web app has no terminal, file tree, Computer use, Computers, Superskills, MCP Marketplace, Memory, Chat Channels or Servers. Those actions are unavailable there, not waiting for approval.
  • Auto-accept permissions in Settings, General approves requests for the open project without a card. Switching it off restores the cards.

Credentials are separate from tool approvals. The local vault stores secrets with rules by command, application or URL. Values are injected at run time and redacted from tool output; they never enter the model context.

Remote and web

Hosted web app

The hosted app at omnia.openfoodpantry.org signs in with the same account. It keeps sessions, prompting and the agent's browser automation, which runs on the hosted server rather than on the device you are using.

Host-only surfaces are left out: terminal, file tree, Computer use, Computers, Superskills, MCP Marketplace, Memory, Chat Channels and the Servers tab. The layout is single column, and the composer sits above the keyboard on a phone.

Paired computers

Settings, Computers pairs another machine by code or through your account. A paired computer runs its own Omnia runtime; this app sends approved actions to it. Stop disconnects it and keeps its credentials. Unpair removes the pairing.

Server CLI

The headless server is the same engine the desktop app runs. Set OPENCODE_SERVER_PASSWORD before starting it:

OPENCODE_SERVER_PASSWORD='a-strong-password' opencode serve --hostname 127.0.0.1 --port 4096

Clients authenticate with HTTP Basic, username opencode and that password, or with an auth_token query value containing base64 of opencode:password. The event stream is SSE on the same origin. A non-loopback listener refuses to start without the password.

Troubleshooting

The window opens after a delay

The sidecar health check waits up to 30 seconds on first start. The window appears when the server reports ready.

The app stays light on GNOME

GNOME 40 carries dark mode only in the GTK theme. Omnia reads gsettings at startup; set the GTK theme to a dark variant, or open Settings, General and set Color scheme to Dark.

Text looks light on GNOME

Electron takes the GTK theme at startup. When the app and the GTK theme disagree, text can render light on a light surface. Open Settings, General and set Color scheme to System, then restart Omnia. To set the GNOME preference directly, run gsettings set org.gnome.desktop.interface color-scheme 'prefer-light' for a light surface or 'prefer-dark' for a dark one.

Login opens a file chooser on KDE

KDE can route the sign-in URL through kioexec. Omnia opens external URLs with gio open on Linux for this reason; if a chooser still appears, set Firefox as the default web browser.

Nothing renders on a virtual machine

Some virtual displays cannot start the GPU process. Launch with ELECTRON_DISABLE_GPU=1 to use software rendering.

Reach the logs

Press Ctrl+K (Command+K on macOS) and run Export logs. Omnia writes opencode-debug-<timestamp>.zip to your Downloads folder with the desktop logs, server logs, crash dumps and network log from the last 24 hours. The live desktop logs sit in logs/ under the app's user data folder; server logs are in ~/.local/share/opencode/log or $XDG_DATA_HOME/opencode/log.
